# Frontend Collection · 截图收藏墙

一个在本地浏览的前端项目截图收藏墙：**页面截图 + 项目名称 + 一行描述**。推荐一并收录源码，方便研究实现与后续复刻；画廊只负责直观展示，有无源码都不影响收录，也不需要 live 演示或公网部署。

原作、源码、说明或演示链接只是可选补充，全部省略也能正常展示。不包含登录、数据库、后台或自动截图服务；当前已收录 [Rive 猫爪按钮](../projects/rive-cat-paw/README.md)，截图来自本地复刻演示。

## 本地运行

使用 Node.js 22 或更高版本。没有第三方依赖，无需执行 `npm install`。

```powershell
cd D:\frontend-awesome-collection\showcase
npm run dev
```

访问 `http://127.0.0.1:5173`。服务仅监听本机；保存文件后手动刷新浏览器，不提供热更新。不要直接双击 HTML 文件，收藏 JSON 需要通过 HTTP 服务读取。这里只需启动收藏墙本身，不需要启动被收藏的项目。

端口被占用时：

```sh
npm run dev -- --port 5174
```

## 添加收藏（截图与描述即可）

1. 将收藏项目的截图放进 `public/covers/`，建议比例 **16:10**，优先选能体现设计特点的截图，避免直接使用很长的整页截图。
2. 编辑 `src/data/projects.json`。文件是一个 JSON 数组，每个收藏是一个对象，顺序即页面展示顺序。
3. 填写项目名称、简短描述和截图路径，保存后刷新页面即可。有源码时推荐一并收录并记录来源，或补充源码仓库链接；暂时没有源码也不影响展示，无需专门创建空项目目录。
4. 可在 `collection.md` 中补充更详细的来源与学习看点。只有以后开始复刻时，才需要维护仓库首页的复刻项目索引；第一版不自动同步 Markdown 清单。

下面就是可以展示卡片的最简记录，仅为格式示例。请替换名称、描述和截图路径，并放入对应图片；`id` 是为每条收藏设置的唯一标识。

```json
[
  {
    "id": "my-first-collection",
    "title": "收藏项目名称",
    "description": "喜欢它的极简排版和留白，之后想研究一下。",
    "cover": "public/covers/my-first-collection.webp"
  }
]
```

| 字段 | 要求 | 用途 |
| --- | --- | --- |
| `id` | 必填且唯一 | 小写英文、数字与短横线组成的稳定标识 |
| `title` | 必填 | 项目名称 |
| `description` | 必填 | 一句描述；卡片内超长文字省略，悬停可查看全文 |
| `cover` | 可选 | `public/covers/` 下的 WebP、PNG、JPG、JPEG 或 AVIF 图片；文件名使用英文、数字、短横线或下划线 |

### 可选链接（不填不影响展示）

无需为了收藏去寻找或搭建演示站。以下字段可以完全省略，也可以填空字符串；只有已有相关链接、且希望附在卡片上时才添加。

| 字段 | 要求 | 用途 |
| --- | --- | --- |
| `demoUrl` | 可选 | 已有的在线演示完整 HTTP(S) 网址 |
| `readmeUrl` | 可选 | 项目说明的完整 HTTP(S) 网址，例如托管平台中的 README 页面 |
| `sourceUrl` | 可选，有源码时推荐填写 | 源码仓库的完整 HTTP(S) 网址 |
| `originalUrl` | 可选 | 原作的完整 HTTP(S) 网址 |

- 没有任何链接时，照常展示截图、名称和描述，不出现链接按钮，也不尝试启动被收藏的项目。
- 只有补充相关链接时，点击封面才按 **演示 → 项目说明 → 源码** 的顺序跳转。
- 原作只作为独立的参考链接，不会被当成自己的复刻演示。
- 未填封面或运行时图片加载失败，会显示“封面待补充”；填写了不存在的图片路径会使构建失败，防止发布坏图。
- **仅在主动填写上述链接字段时**，才要求完整 HTTP(S) 网址，不接受磁盘路径或仓库相对路径。这个校验不适用于 `cover`：截图使用上面示例中的本地相对资源路径，不需要上传图床。所有外部链接在新标签页打开。
- 页面上的“收录指南”可查看和复制记录模板；它不是在线编辑器，不会写入本地文件。
- 仅做收藏时，将截图保存在 `public/covers/` 即可；以后开始复刻，再按需将额外的参考图和复盘截图放进具体项目的 `screenshots/`。

## 构建与预览（按需）

日常本地收藏只需 `npm run dev`。下面的构建或线上托管不是收录项目的前提。

```sh
npm test
npm run build
npm run preview
```

构建会校验数据和封面是否存在，将站点文件复制到 `dist/`。预览同样默认使用 5173 端口；如果开发服务仍在运行，请使用 `npm run preview -- --port 4173`。

部署时将 **`dist/` 的内容** 放到静态网站托管服务。资源路径为相对路径，可放在域名根路径或子目录下。这里不预设部署平台，也不自动发布。

构建会覆盖当前文件，但不会删除上次构建留下的旧封面。需要移除旧资源时，确认路径后手动清理 `showcase/dist/`，再重新构建。

## 文件结构

```text
showcase/
├── index.html                 # 页面结构与收录指南
├── package.json               # 本地运行、测试和构建命令
├── public/
│   ├── favicon.svg
│   └── covers/                # 展示封面
├── src/
│   ├── app.js                 # 加载作品、渲染卡片与弹窗交互
│   ├── projects.js            # 数据校验、模板与跳转规则
│   ├── styles.css             # 响应式布局和视觉样式
│   └── data/projects.json     # 收藏清单，包含猫爪按钮记录
├── scripts/                   # 零第三方依赖的本地服务与构建脚本
└── tests/                     # 数据校验和本地服务测试
```

收藏墙与被收藏的项目独立：即使 `projects/` 目录中没有任何源码，也能展示截图收藏。之后要进行复刻时，再为对应项目选择技术栈和运行方式。
